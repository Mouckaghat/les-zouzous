# JTCI-002 · Les Zouzous Multilingual Intelligence
Status: IN DEVELOPMENT · CR-001 · 2026-11-09

## Boundaries
- Translator remains the one-way translation experience.
- Communicator is the only place for Conversation and Live Listening.
- Lili Visual remains separate and unchanged.
- Production main must not receive changes without review and acceptance.

## Existing baseline (source audit)
- Next.js 15 / React 19 / TypeScript.
- Main interface: app/page.tsx, currently a client component.
- Existing translation endpoint: app/api/translate.
- Browser speech and voice features require a capability and permission audit.
- Source language options already include FR, DE, EN, RU, KO, JA, ZH, SV, IT.

## CR-001 scope
1. Conversation: reliable two-way French/German voice and text with explicit language routing and spoken replies.
2. Live Listening: opt-in microphone capture; later optional supported tab audio capture; live translated captions.
3. Study: ask for a word, hear a target-language pronunciation, review examples.
4. Memory: opt-in, persistent, editable vocabulary; consent and deletion controls before production enablement.
5. Quality: measurable acceptance and release gates, regression evidence and defects register.

## Acceptance tests
| ID | Scenario | Pass condition |
| --- | --- | --- |
| QA-001 | FR -> DE | Correct written translation and intelligible German speech |
| QA-002 | DE -> FR | Correct written translation and intelligible French speech |
| QA-003 | KO live audio -> EN | Continuous readable captions without significant omissions |
| QA-004 | Speaker turns | No wrong-language routing in a controlled 20-turn test |
| QA-005 | Vocabulary persistence | Approved entry can be recalled after a new session |
| QA-006 | Privacy | Capture is opt-in, visible and can be stopped; no silent storage |
| QA-007 | Permissions | Denied microphone permission gives clear recovery guidance |
| QA-008 | Regression | Translator and Lili Visual continue functioning |
| QA-009 | Latency | Median phrase-end to translated text <= 3s on reference network/device |
| QA-010 | Cost | Usage metering and budget safeguards enabled |

## Release gates
- No open critical privacy, safety or translation-routing defects.
- Evidence captured for every acceptance test, with device/browser and language.
- Health score >= 90%, with no critical category failure.
- Preview deployment verified and approved before merge to main.

## Health score weights
Translation accuracy 30%; voice quality 20%; latency/stability 20%; continuity 15%; memory/privacy 10%; usability 5%.
Unmeasured criteria remain N/A, never reported as 100%.

## Risks
- Browser microphone and tab-audio availability vary.
- Overlapping speakers and language auto-detection can misroute.
- Streaming speech/translation costs need caps.
- Speech recordings and vocabulary need explicit consent and retention rules.
- Vercel preview must not expose production credentials or stored family data.

## Delivery sequence
1. Audit existing Communicator and translate endpoint.
2. Add Conversation / Live Listening submodes without breaking current UX.
3. Implement consent-based audio capture, reliable cleanup, and error states.
4. Integrate server-authenticated streaming transcription and translation.
5. Add spoken playback and evaluate eight target languages.
6. Add persistent vocabulary with access control and quality dashboard.

## Change control
CR-001 is approved in principle by the request to begin implementation; each material scope change requires a recorded CR. Defects receive QA identifiers and verified closure. This document is a GitHub-side starting record; Juralou ACE synchronization is not yet implemented.
